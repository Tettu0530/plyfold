# Internationalization (i18n) rules

The UI is available in Japanese, English and Simplified Chinese. Korean can be added just by adding dictionary files.

## How it works

- Implementation: `apps/desktop/src/i18n/index.ts`
- Dictionaries: `apps/desktop/src/i18n/<lang>/<namespace>.ts`. **Japanese (`ja/`) is the source**; the other languages are typed as `Record<keyof typeof source, string>`, which enforces the same keys (missing or extra keys are type errors)
- Each namespace notes in its header comment which files its strings belong to. Only touch `ja/index.ts` and `en/index.ts` when adding a new namespace
- Inside components: `const t = useT();` → `t("sidebar.newSession")`. Components re-render when the language changes
- Outside components (stores, lib): `t()` from `import { t } from "@/i18n"`. It looks up the language current at call time
- Language setting: "Language" in Settings (`language` in `settings.json`; `auto` follows the macOS language, falling back to English)

## Writing strings

- Keys are meaningful lowerCamelCase English names (`newSession`, `commitPlaceholder`). Don't make long keys that copy the sentence
- Interpolation is `{name}`. Strings whose form depends on a count use ICU plurals: `"{count, plural, one {# file} other {# files}}"` (`#` is the count). Japanese can simply use `"{count} 件"` (it has no plural distinction)
- Don't build sentences out of pieces. Word order differs between languages, so make each sentence one key and pass values in by interpolation (`"「{title}」を消します"` / `"Delete “{title}”"`)
- Never translate: commands, paths, identifiers, ACP and git terms (`worktree`, `diff`, `model`, `effort`, `mode`, `--no-ff`), key combinations (the `Keys` component), provider and agent names (Claude Code, Codex, OpenCode, Gemini CLI)
- Code comments are written in English
- Translate `aria-label`, `title` and `placeholder` too
- Translate developer screens (the motion lab) too

## English style

- Sentence case: "New session", "Open in editor". The same for headings and buttons (no Title Case)
- Buttons are short imperatives starting with a verb: "Stop", "Merge", "Create PR", "Discard". No period
- Descriptions are short declarative sentences ending with a period. Don't start with "You can …" or "Please …". No exclamation marks
- States are short adjectives or participles: "Working", "Waiting for permission", "Stalled", "Idle", "Stopped"
- Short time forms: `12s`, `3m`, `2h`, `yesterday`, `5d`
- Pluralize units correctly ("1 file" / "2 files"). Don't mechanically translate the Japanese counter 「件」 as "items"; say what is being counted
- Don't turn the Japanese 「〜します」 into "Will …". Describe the UI in the present tense

## Simplified Chinese style

- The target is Simplified Chinese as used in mainland China (zh-CN). Never use Traditional characters. Choose the short, plain terms common in software UIs
- Buttons are mostly 2 to 4 character verbs: 「停止」「合并」「放弃」「复制」「发送」. No full stop
- Descriptions end with 「。」. Use 「请」 only in sentences that ask the user to do something (e.g. 请先提交), and don't overuse it. No exclamation marks
- Use full-width punctuation (，。：（）「」), but keep half-width brackets and symbols attached to Latin letters, digits, code or paths
- Put a half-width space between Chinese and Latin letters or digits (「打开 worktree」「3 个文件」)
- Counts take a measure word (「3 个文件」「2 个会话」「5 轮」). There is no plural distinction, so ICU plurals need only `other`
- Short time forms: `12秒`, `3分钟`, `2小时`, `昨天`, `5天`

## Fonts and glyphs

- Some kanji/hanzi have different glyph shapes in Japanese and Chinese (「直」「骨」「誤」 etc.). The UI language is declared with `<html lang>` (`ja` / `en` / `zh-CN`), and `--font-cjk` in `index.css` is switched with `:root:lang(..)` (Hiragino Kaku Gothic for Japanese, PingFang SC for Chinese)
- Conversation text (agent output, the user's own messages, thinking) is rendered in the language of the text itself, independent of the UI language: put `contentLang(text)` (`ja` if it contains kana, `ko` if it contains hangul) into `lang`, and switch fonts with selectors such as `[lang="ja"]`

## Adding a language (Chinese, Korean)

1. Under `src/i18n/<lang>/`, create one file per namespace with the same shape as `en/` (the types point out missing keys)
2. Add the language to `Lang`, `LANGS`, `HTML_LANG`, `DICTS`, `detectLang` and `resolveLang` in `src/i18n/index.ts`, and to `AppSettings.language` in `lib/types.ts` (the Settings options are built from `LANGS`)
3. Kanji/hanzi and hangul fonts: add a `--font-cjk` rule with `:root:lang(..)` in `index.css` (PingFang SC for Chinese; rendering with the Japanese font gives Japanese glyph shapes)
4. Engine strings: add the language to `Lang`, `set_lang` and the `tr!` arguments in `crates/plyfold-i18n`, then add a string to every `tr!` call (none can be skipped)
